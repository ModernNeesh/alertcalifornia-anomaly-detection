# Quality of Service Anomaly Detection in Wildfire Monitoring Networks
*Understanding how Vision Transformers can act as effective models for anomaly detection in outdoor cameras.*

## Structure of Repository

This repository contains the code used to obtain the results in our paper, *Quality of Service Anomaly Detection in Wildfire Monitoring Networks*, which can be found here (link pending). The folders are structured as follows:

* `camera_data`: contains the following:
  * The `dataframes` folder contains the training, validation, and test data used during training
  * The `images` folder is, by default, where images are downloaded to.
  * All raw data pulled from LabelStudio is also present here. CSV files contain only labeled data, while JSON files contain both labeled and unlabeled data.
* `embedding_data` stores the embeddings generated by the model during inference.
* `outputs` contains the predictions and throughput results from inference tests
* `src` contains the library code used throughout the paper
* `weights` contains the model weights generated by the various scripts.

Meanwhile, some scripts are also available to run:

* `model_test_runs_triplet.ipynb`, `model_test_runs_deepsad.ipynb`, and `model_test_runs_hierarchical.ipynb` contain code that reproduces the baseline models we obtained from each of the following objective functions: triplet margin loss, DeepSAD, and Hierarchical SAD (H-SAD), respectively. Explanations of these functions can be found in our report linked above.
* `model_test_runs_finalized.ipynb` contains code that reproduces the finalized model we obtained and demonstrates its generalizability to the training set.
* `run_inference.py` uses a pre-trained model to run inference on a specified set of data. By default, this is the combined training, validation, and testing datasets.
* `inference_analysis.ipynb` analyzes the results obtained after running `run_inference.py`.

## Instructions

### 1. Create a virtual environment and install dependencies
  Make sure you have:

- Python 3.12 installed  
- `pip` installed

Check versions:

```bash
python --version
pip --version
```

#### Windows
```powershell
python -m venv venv
venv\Scripts\activate.bat
pip install -r requirements.txt
```

#### macOS / Linux
```bash
python3 -m venv venv
source venv/bin/activate
pip3 install -r requirements.txt
```

### 2. Ensure necessary files are included
  In order to train a model and/or perform inference, labeled data from LabelStudio is necessary and must be in the form of a CSV file. This data is not publicly available. The following instructions pertain to those who have access to the file containing the data.
  There are three files necessary to reproduce our results. The first is `coronado_hills_data.csv`, obtained from exporting our labeled results from Label Studio. This data is used in `model_test_runs_triplet.ipynb` to train a model using triplet loss. The second is `coronado_hills_data.json`, which is obtained by exporting *all* results from Label Studio. This data is used in `model_test_runs_deepsad.ipynb` and `model_test_runs_hierarchical.ipynb` to train baseline models using the DeepSAD objective and H-SAD objective, respectively.
  Additionally, the combined training set data and unseen set data must also be included. The training set data contains the concatenated labeled results from the Coronado Hills S, Mesa Grande N, and Palomar Observatory 1 Label Studio projects. This file, by default, must be named `training_set_cameras_data.csv`. Meanwhile, the test set data concatenates the labeled results from the Berryessa, Toro Peak 1, and Dewdrop 1 Label Studio projects. This file, by default, must be named `unseen_set_cameras_data.csv`. During concatenation, a column named `location` is added by extracting the location name from the image URL. 

### 3. Run program(s)

#### Model training notebooks

For the simplest experience, it is recommended to run all the cells in `model_test_runs_finalized.ipynb` as they appear. This will generate a model that can be used to perform inference. After doing so, you can proceed to the next section. The rest of the current section outlines optional scripts that may be run to reproduce our paper's results. 

To reproduce our paper's results, run `model_test_runs_triplet.ipynb`, `model_test_runs_deepsad.ipynb`, and `model_test_runs_hierarchical.ipynb`, and `model_test_runs_finalized.ipynb`. It is highly recommended to run all settings in these notebooks as they appear; however, some customization options are outlined in the notebooks themselves. Each of these notebooks will train a model and save it to the `weights` folder by default. At the end of each notebook, the training and validation (or test for the final model) accuracies can be viewed. 

#### Running inference

##### `run_inference.py`

To analyze our model's outputs, you may first run `run_inference.py`. However, if you do not wish to perform inference, you may skip this step and directly run `inference_analysis.ipynb`. 

By default, this script performs inference on the combined training, validation, and test data, but this behavior can be changed. 

If you wish to use the default settings (recommended), simply run:
  ```powershell
  python run_inference.py
  ```
If you wish to customize the behavior of this script, you may view the provided arguments by running the following command:
  ```powershell
  python run_inference.py -h
  ```

**IMPORTANT**: If you changed the data used to perform inference, you must also make changes in `inference_analysis.ipynb`. The changes you must make are outlined in the notebook itself. 

After running this script, the predicted labels of the input data will be saved to `inference_results.csv`, while the throughput results will be saved to `throughput_results.csv`.

##### `inference_analysis.ipynb`

To analyze the results from running `run_inference.py`, run `inference_analysis.ipynb`. Examples from previous runs of this script are already provided in the `outputs` folder. If you wish to use your own results, the process to do so is outlined in the notebook itself. 

### 4. Visualize Results

#### Embedding Visualization Tool

For simplicity, the `embeddings.json` file used to load the visualization tool is provided in the `embedding_data` directory. This file contains the reduced PCA embeddings for each image in the training dataset, along with their corresponding class labels. Additional features—including `daytime`, `hour`, and `season`—were subsequently added to enable further analysis of the embedding space.

To explore the embedding space, open `index.html` in a live server environment. This will launch an interactive visualization interface that lets you explore the embeddings produced by our training and analyze patterns across the dataset.

If you prefer, you may also view the visualization [online](https://dsc180.dronelab-nathan-2.ucsd.edu/). 

All projection visualizations in our report were generated using this tool and can be replicated by selecting the same parameters.
